# Concat 安卓平板模式 + Release APK 打包计划

## Context（背景）

Concat 是 Rust + Slint 的跨平台视频编辑器。当前 Android 端把平板当作"大号手机"：activity 锁死竖屏、强制手机壳 UI（`ui/phone/`），代码注释明确写着"在做出宽屏壳之前，activity 保持竖屏，平板也包括在内"（对应上游 issue #221/#222/#229 的遗留待办）。

本任务：**新增安卓平板模式 —— 运行时检测平板后复用 Windows 桌面的 Workspace 界面（标题栏 + 四栏可停靠工作区），放开旋转；然后在本机打一个 Release APK**。项目已有大量现成基础设施可直接复用（safe-area、860px 紧凑 dock 断点、桌面壳的双形态启动屏），核心改动集中在平台判定与入口层，UI 层基本零改动。

## 一、平板模式代码改动（约 120 行）

### 1. `src/crates/concat/src/platform.rs`
- 新增 `static TABLET: AtomicBool` + `pub fn set_tablet(bool)` / `pub fn tablet()`（供 Android 入口在启动时注入）。
- 修改 `phone()`（412-415 行）：Android 上改为 `CONCAT_PHONE 环境变量 || !tablet`（平板不再算手机；检测失败兜底为手机壳，保持现状安全）；iOS 仍恒为 phone；桌面行为不变（`CONCAT_PHONE=1` 预览手机壳照旧）。同步更新 402-411 行的文档注释。
- `OWN_WINDOW_BUTTONS`（590 行）改为函数 `pub fn own_window_buttons() -> bool { !MACOS && !cfg!(any(target_os = "android", target_os = "ios")) }`——平板上桌面标题栏不画最小化/最大化/关闭按钮（Android 全屏无窗口按钮），`app.slint:200` 的 `no-frame` 也随之在 Android 上保持关闭。

### 2. `src/crates/concat-android/src/lib.rs`（`android_main`，514 行）
- 在 `slint::android::init` 之后、`concat::run()` 之前，用现有 `java::with_class` JNI 辅助（124 行）读取 `activity.getResources().getConfiguration().smallestScreenWidthDp`：**≥ 600（Android 官方平板阈值）判定为平板**，调用 `concat::platform::set_tablet()`。JNI 异常或读不到 → 按手机处理（兜底）。
- 若判定为手机：JNI 调 `activity.setRequestedOrientation(SCREEN_ORIENTATION_PORTRAIT)` 保持今日竖屏行为；平板：不锁定，自由旋转（旋转不重建 activity，`config_changes` 已含 orientation|screenSize，窗口 resize 后现有 860px 断点自动在四栏工作区/紧凑双栏间切换）。

### 3. `src/crates/concat-android/Cargo.toml`（81 行）
- `orientation = "portrait"` → `"fullUser"`，更新注释（竖屏锁移交运行时按设备类型决定）。

### 4. `src/crates/concat/src/lib.rs`（681 行）
- `app.set_own_window_buttons(platform::OWN_WINDOW_BUTTONS)` → `platform::own_window_buttons()`，配合上面改动。

### 5. UI 层（预期零或极小改动）
平板 = `phone=false` 后自动获得 Windows 同款界面：`app.slint:716` 显示 TitleBar、`:773` 显示 Workspace（四栏 dock）、启动屏自动 WideHome、设置对话框桌面形态、safe-area 内边距已内建（`app.slint:708-711`）。触摸操作走 Slint TouchArea（分割条拖拽/菜单点按原生支持）。验证阶段若发现触摸目标过小等问题再微调，不预先扩大范围。

## 二、验证

1. 代码完成后：`cargo check -p concat-android --target aarch64-linux-android` 编译通过。
2. 桌面回归：`cargo run -p concat`（Windows 桌面界面不受影响）；`CONCAT_PHONE=1 cargo run`（手机壳不受影响）。

## 三、打包构建（Release，aarch64）

1. **环境检测与按需安装**（用户选择"帮我检测"）：检测 JDK17 / ANDROID_HOME / NDK / rustup target `aarch64-linux-android` / cargo-apk；缺什么装什么（SDK 用 cmdline-tools 装 platforms;android-35 + build-tools + platform-tools + NDK，winget 装 JDK17）。
2. **FFmpeg 交叉编译**（`src/scripts/ffmpeg-mobile.sh aarch64-linux-android`，产出 `src/vendor/ffmpeg/<target>`）：
   - 优先检测 WSL → 有则在 WSL 内跑（与官方 CI 完全一致，最稳）；
   - 无 WSL → Git Bash 原生跑（需 winget 补 GNU make，处理 MSYS 路径转换：`MSYS_NO_PATHCONV` 或改传 `clang.exe` + 显式 `--target`）。
3. `src/scripts/android-libs.sh aarch64-linux-android`（拷贝 libc++_shared 到 jniLibs）。
4. 构建：`cd src && eval "$(scripts/mobile-env.sh aarch64-linux-android)" && cargo apk build --release -p concat-android --target aarch64-linux-android`。
5. 产物 `src/target/release/apk/Concat.apk` → 复制为 `dist/Concat-<版本>-android-arm64.apk`（版本读自 `src/Cargo.toml`，当前 0.2.9），并告知侧载安装方法。

## 风险与预期

- 首次 Release 编译约 **1-3 小时**（Skia + wgpu + whisper + FFmpeg 全量交叉编译），磁盘占用约 40GB（target 目录），全程需联网。
- FFmpeg 在 Windows 宿主机构建若反复失败，兜底方案是安装 WSL（约 2GB 下载，届时先征求同意）。
- APK 使用调试密钥签名（cargo-apk 默认），可直接侧载安装；未含正式发布签名。
